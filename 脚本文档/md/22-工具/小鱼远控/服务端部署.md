# P2P 服务端部署

**信令服务只需要一个编译后的程序和一个配置文件。服务器不用安装 Go，默认 HTTP，不需要域名或证书。**

## 1. 取得程序

在装有 Go 的开发电脑、项目根目录运行：

```powershell
.\services\remote-signal\发布.ps1
```

输出在 `dist/remote-signal/`，默认是 Linux x64 程序；需要 Windows x64 时加 `-TargetOS windows`。使用仍受支持的 Go 版本编译。把输出的 `config.example.json` 改名为 `config.json`。

最终上传到服务器的是：

```text
xiaoyv-signal
config.json
```

## 2. 填写配置

```json
{
  "listen": "0.0.0.0:8080",
  "keys": ["REPLACE_WITH_RANDOM_CONNECTION_KEY"],
  "stun": ["stun:YOUR_STUN_SERVER:3478"]
}
```

- `listen`：信令监听地址和端口，示例使用 TCP 8080，服务器需放行该端口。
- `keys`：将占位内容替换为至少 32 字符的随机连接码，电脑与手机填写同一个码；不同码隔离不同组。
- `stun`：替换为可用的 STUN 服务地址，**不是信令服务的 HTTP 地址**。

## 3. 运行

在程序所在目录执行：

```bash
./xiaoyv-signal -config config.json
```

Windows 使用 `xiaoyv-signal.exe -config config.json`。然后电脑和手机的信令地址都填 `http://服务器公网IP:8080`，继续按 [P2P 连接](P2P连接.md) 设置。修改配置后重启程序生效。`http://服务器公网IP:8080/healthz` 可检查信令服务是否响应。

## STUN 与可选配置

Go 程序只负责信令，**不内置 STUN**。可使用已有的 STUN 服务；如果自己提供，需要另外运行 coturn。有可用 STUN 也不保证所有网络都能打洞成功。

默认不启用中继。需要时，在配置中增加 `turn: ["turn://服务器:3478"]` 和 `turn_secret`，后者需与 coturn 的 `static-auth-secret` 一致、至少 32 字符；电脑和手机也都需勾选“允许中继”。coturn 配置示例保留在源码的 `services/remote-signal/turnserver.conf.example`，不随信令程序发布。当前只支持 UDP TURN，中继会消耗服务器流量。

HTTPS 仍可选：配置 `tls_cert` 和 `tls_key` 为证书及私钥路径即可。使用 HTTP 时连接码和信令明文传输。
