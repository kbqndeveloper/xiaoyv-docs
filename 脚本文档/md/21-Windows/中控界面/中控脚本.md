# 中控脚本 center.lua

支持内置 Worker 的中控会自动运行 `center.lua`，无需点击启动。文件位置见 [开发与打包](../开发与打包.md)；HTML 模式在页面桥就绪后运行一次，原生模式直接运行。刷新网页不重跑脚本；缺少文件或使用不含内置 Worker 的中控时不运行。

这是独立的中控 Worker，不出现在普通窗口列表，ID 为 `__center__`；删除普通窗口不会结束它。它与普通进程内窗口各有自己的 Lua VM，位数均与中控相同，共享进程及插件的进程级状态。关闭中控时会请求脚本停止，并等待清理。

## Lua 控制接口

以下 `center` 表仅提供给中控脚本，与 HTML 中的 JavaScript `center` 表不是同一套函数签名。普通窗口不自动获得此表。控制接口在原生界面也可用，不要求页面注册函数。

**方法名称：** 中控脚本控制接口。

**语法：** 见下方方法表。

**参数说明：**

| 方法 | 参数 | 返回值 |
|---|---|---|
| `center.request(command, params, timeoutMs)` | 命令名、参数表（默认空表）、可选超时毫秒 | 成功返回 `{response, messages}`；失败返回 `nil, error`。 |
| `center.workers(timeoutMs)` | 可选超时 | 成功返回窗口消息数组、响应表；不含中控 Worker。 |
| `center.logs(workerId, limit, after, timeoutMs)` | 窗口 ID、条数、游标、可选超时；条数和游标可省略 | 成功返回日志消息数组、响应表。 |
| `center.add(path, arch, name, timeoutMs)` | 可省略：脚本路径、架构（默认 `"x86"`）、名称、超时；`arch` 为 `"x86"`、`"x64"` 或 `"inProcess"` | 成功返回新窗口 ID、响应表；只创建，不运行。进程内模式使用中控自身位数。 |
| `center.remove(workerId, timeoutMs)` | 窗口 ID、可选超时 | 同 `request`；删除窗口。 |
| `center.start(workerId, timeoutMs)` | 窗口 ID、可选超时 | 同 `request`；启动脚本。 |
| `center.pause(workerId, timeoutMs)` | 窗口 ID、可选超时 | 同 `request`；请求暂停。 |
| `center.resume(workerId, timeoutMs)` | 窗口 ID、可选超时 | 同 `request`；继续脚本。 |
| `center.stop(workerId, timeoutMs)` | 窗口 ID、可选超时 | 同 `request`；请求停止并清理。 |
| `center.terminate(workerId, timeoutMs)` | 窗口 ID、可选超时 | 同 `request`；强制结束外置窗口，进程内不支持。 |

| 返回值 | 说明 |
|---|---|
| 成功结果 | 各方法的返回结构见上表；`response` 为控制响应，`messages` 为查询消息数组。 |
| `nil, error` | 请求失败，第二返回值为错误文本。 |

**详细说明：**

上述方法失败均返回 `nil, error`。可选超时沿用 [ui.call](call.md) 的规则；控制成功只表示命令已接纳，实际运行状态从 `center.workers()` 返回的 `state` 查看。`add` 不传路径时沿用中控默认脚本；`arch` 只接受 `x86`、`x64` 或 `inProcess`。进程内窗口需要先停止并完成清理才能删除。

**使用示例：**

```lua
-- center.lua：创建一个外置 x86 窗口并运行默认脚本
local id, err = center.add(nil, "x86", "采集窗口")
assert(id, err)
local result, startErr = center.start(id)
assert(result, startErr)

local workers, response = center.workers()
assert(workers, response)
for _, worker in ipairs(workers) do
    print(worker.workerId, worker.workerArch, worker.state)
end
```

日志消息的 `id` 是序号，`text` 是正文；响应表 `data` 为 JSON 字符串，包含 `first`、`next` 游标。继续拉取时把 `next` 传给 `after`，不要把第二返回值当作 JavaScript 的日志对象。

页面与中控脚本仍通过 [ui.call](call.md) 和 [ui.receive](receive.md) 交互：页面向 `ui.send("__center__", "settings", data)` 投递，中控脚本通过 `ui.receive()` 接收。需要持续接收事件时应在脚本里保留接收循环；脚本执行结束后不再接收。
