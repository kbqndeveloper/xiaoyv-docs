# 开发与打包

中控启动参数可指定一个 `.lua` 或 `.alpkg`；不带参数时，按以下顺序选择来源：

1. 中控同目录的 `dev.lua`；
2. 中控同目录的 `main.alpkg`；
3. 两者都不存在时，暂不设置普通窗口的默认脚本。

界面、中控脚本和普通窗口默认入口使用同一个来源，不跨目录或跨包补找：

| 启动来源 | 界面 | 自动运行的中控脚本 | 普通窗口默认入口 |
|---|---|---|---|
| `.lua` | 该脚本目录的 `center.html` | 同目录 `center.lua` | 指定的 Lua 文件 |
| `.alpkg` | 包内 `ui/center.html` | 包内 `center.lua` | 打包配置的 `entry` |
| 未找到默认脚本 | EXE 同目录 `center.html` | EXE 同目录 `center.lua` | 暂无 |

缺少页面时使用原生界面，缺少 `center.lua` 时不运行中控脚本。包模式不会被 EXE 旁的同名文件覆盖。使用包内中控时，记得将 `center.lua` 和 `ui/` 页面资源纳入打包白名单。原生界面在没有默认脚本时，首次增加窗口会选文件，并设为后续窗口的默认路径；给单个窗口显式传入 `path` 只影响该窗口。已有窗口不随默认路径改变，更换整个项目请重新打开中控。

普通窗口创建后需要手动启动；`center.lua` 自动执行，详见[中控脚本](中控界面/中控脚本.md)。独立双击 `XiaoYvWorker.exe` 或 `XiaoYvWorker64.exe` 时只运行其同目录的 `main.alpkg`，等待脚本结束后退出。

`dev.lua` 用于开发调试，可以通过 `require/loadfile/dofile` 加载同目录内的相对 Lua 文件。

## 打包

Windows 开发目录中的打包器位于 `.xiaoyv/xiaoyv_pack.exe`，同目录 `windows.key` 必须与 Worker 构建所用的 Key 对应。打包器每次从文件读取 Key，不把 Key 编入打包器自身。

例如在程序目录执行：

```powershell
.\.xiaoyv\xiaoyv_pack.exe "E:\我的项目"
```

参数是配置目录，打包器读取其中的 `alpkg.json`；无参数时使用当前工作目录，不默认遍历 EXE 的上级目录。配置不存在时自动生成，首次使用请核对入口、白名单和路径。

`input_path`、`output_path` 相对于配置目录解析。新生成配置的默认值为：

| 配置位置 | input_path | output_path |
|---|---|---|
| 普通项目目录 | `.` | `dist/main.alpkg` |
| `.xiaoyv` 目录 | `../` | `../dist/main.alpkg` |

第二个命令行参数可覆盖输出文件：

```powershell
.\.xiaoyv\xiaoyv_pack.exe "E:\我的项目" "E:\发布目录\main.alpkg"
```

项目必须使用带 `include` 白名单的 `alpkg.json`，详细规则见[脚本包打包规则](../06-脚本包/打包规则.md)。完成后控制台显示实际打包的一级文件、一级目录统计、文件总数和包大小。Windows 默认打包启用加密并保留文件名、行号等调试信息。发布时将包命名为 `main.alpkg`，放在程序目录；运行端不需交付 `.xiaoyv/windows.key` 和打包器。

## 插件与目录

新增窗口可选 x86、x64、进程内。前两项分别使用独立的 `XiaoYvWorker.exe`、`XiaoYvWorker64.exe`；进程内窗口使用中控自身位数，可以创建多个。选择只影响新增窗口，不修改已有窗口。不同运行位置的停止、删除和故障影响见[中控交互](中控交互.md)。

`require("名称")` 加载小鱼原生插件时，按以下顺序查找同名 DLL：

| Worker | 首选 | 文件不存在时继续查找 |
|---|---|---|
| x86 | `runtime/x86/名称.dll` | `runtime/名称.dll` |
| x64 | `runtime/x64/名称.dll` | `runtime/名称.dll` |

这些目录相对于当前 EXE（进程内为中控 EXE），不是 Lua 脚本目录。仅文件不存在时回退；已找到但位数错误、缺少依赖或加载失败时保留原始错误，不偷偷换用其他 DLL。没有固定名称映射，改名后 `require` 也要使用新名称。普通第三方 DLL 并非都能直接 `require`，C 接口可通过 FFI 调用，且位数必须一致。

- `xiaoyv_hcbyj.dll`：x86 大漠插件；本体 `hcbyj.dll` 仍在 Worker EXE 同目录。
- `db.dll`：分别提供 x86、x64 版本。
- `opencv.dll` 和对应 OpenCV SDK DLL：可选，默认构建不包含。
- `VMmemory.dll` 及依赖：可选，仅 x64，默认构建不包含。

`runtime` 下的 `luasocket/` 存放共用 Lua 文件；许可证仍放在 `runtime/licenses`，不移入位数目录。使用哪个插件就保留对应 DLL 及其依赖。Worker 间跨位数调用使用 [RPC](RPC/概述.md)，不能直接把 x64 DLL 加载到 x86 Worker 内。

普通双击或不带控制参数启动中控时，不会开放外部控制入口。需要由命令行脚本、AI 或其他本机工具控制 Worker 时，使用 `--enable-control` 启动中控；完整命令见[中控外部控制](中控外部控制.md)。

## 自定义中控页面

按上面的来源表找到页面就进入 HTML 模式，没有则显示原生界面。`center.default.html` 只是参考模板，不会被自动选为运行页面；有 HTML 但加载失败时不回退，仍按原来的方式提示错误。

`center.html` 整个文件都可修改，没有必须保留的 DOM、CSS 或按钮。原生中控会向本地顶层页面自动注入 `center` 和 `ui`，接口说明见 [HTML 中控自定义与 JavaScript 接口](中控界面/HTML自定义与JavaScript.md)。保存后按 `Ctrl+R` 刷新页面即可，刷新不会停止正在运行的 Worker，也不会重跑 `center.lua`。包内页面需重新打包并重启中控。关闭中控会结束外置 Worker，并等待进程内脚本停止及清理。

每次构建都会更新 `center.default.html` 作为出厂参考模板；已经存在的 `center.html` 不会被覆盖，只有缺少它时才从参考模板创建。更新程序后如需采用新版模板，应自行对照合并，不要直接覆盖尚未备份的定制页面。

仅 HTML 模式需要电脑已安装的 Microsoft Edge WebView2 Runtime。无法打开页面时先安装或修复该 Runtime，或从当前来源移除页面后重启为原生模式。页面可通过文件接口保存配置；网页桥不提供独立弹窗、自动重连或渲染进程崩溃恢复功能。
