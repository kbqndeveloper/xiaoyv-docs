# RapidOCR 本地插件

Windows 可选 OCR 插件，通过 CPU 在本机识别图片和原始像素，不需要启动 HTTP 服务。原有的 [RapidOCRWeb](../RapidOCRWeb.md) 是另一种服务调用方式。

```lua
local ocr = require("rapidocr")
local result, err = ocr.read("截图.png")
assert(result, err)
print(result.text) -- 全部文字
for _, item in ipairs(result.items) do
    print(item.text, item.x, item.y, item.score)
end
```

`require` 加载插件，不加载模型。第一次识别自动为名称 `default` 加载 `server` 预设；需要提前加载或使用多个模型时调用 [init](init.md)。通过识别选项 `model` 选择名称，省略时使用 `default`；各 Lua VM 独立管理模型。

| 预设 | 模型 | 选择依据 |
|---|---|---|
| `server`（默认） | PP-OCRv5 server 检测、识别；LCNet_x1_0 方向分类 | 模型较大，优先考虑识别效果 |
| `mobile` | PP-OCRv5 mobile 检测、识别；LCNet_x0_25 方向分类 | 模型较小，优先减少资源占用 |
| `english` | PP-OCRv5 英文 mobile 识别；检测、方向分类复用 `mobile` | 用于英文场景 |

也可提供自己的检测、识别、字典和可选方向分类模型，配置见 [init](init.md)。各预设的实际速度与效果取决于设备和图片。

所有识别、找字入口均支持 `allowlist` 解码白名单，用法见 [单行识别选项](readLine.md)；省略或传空字符串时保持原来的识别行为。

## 部署

将与 Worker 位数一致的三个 DLL 放在 `runtime/x86/` 或 `runtime/x64/`：

- `rapidocr.dll`
- `onnxruntime.dll`
- `onnxruntime_providers_shared.dll`

目标电脑需预装对应位数的 Microsoft Visual C++ 运行库。无需另外部署 OpenCV DLL。

预设模型按下面的目录放置，x86、x64 共用；运行时不联网下载模型。使用自定义模型时，由 `init` 指定文件路径。

```text
runtime/rapidocr/
├─ mobile/
│  ├─ det.onnx
│  ├─ rec.onnx
│  └─ cls.onnx
├─ server/
│  ├─ det.onnx
│  ├─ rec.onnx
│  └─ cls.onnx
└─ english/
   └─ rec.onnx
```

## 接口

| 方法 | 用途 |
|---|---|
| [ocr.init](init.md) | 加载预设或自定义模型 |
| [ocr.read](read.md) | 从图片文件识别全部文字 |
| [ocr.findText](findText.md) | 从图片文件查找文字框 |
| [ocr.readPixels](readPixels.md) | 从原始像素识别全部文字 |
| [ocr.findTextPixels](findTextPixels.md) | 从原始像素查找文字框 |
| [ocr.readLine](readLine.md) | 从已裁好的单行图片直接识别文字 |
| [ocr.readLinePixels](readLinePixels.md) | 从已裁好的单行像素直接识别文字 |
| [ocr.isLoaded](isLoaded.md) | 查询指定名称的模型是否已加载 |
| [ocr.release](release.md) | 释放指定名称的模型 |

返回坐标均以输入图片左上角为原点。插件不自动截图，也不添加屏幕或窗口偏移。
