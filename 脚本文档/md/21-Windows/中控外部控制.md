# 中控外部控制

`xiaoyvctl.exe` 用于从命令行查询中控窗口、启动或停止脚本、读取日志。

## 启用控制

外部控制默认关闭。启动中控时显式添加 `--enable-control` 才会启用：

```powershell
XiaoYvCenter.exe "E:\我的项目\main.alpkg" --enable-control
```

然后用同一 Windows 用户运行下面的命令。`--enable-control` 不会自动启动普通窗口。

## 命令

| 命令 | 说明 |
|---|---|
| `xiaoyvctl centers` | 列出已启用外部控制的中控进程 ID。 |
| `xiaoyvctl [--pid PID] workers` | 列出 Worker ID、位数、进程 ID、脚本路径、运行状态和常驻文本。 |
| `xiaoyvctl [--pid PID] add [script] [--arch x86\|x64\|inProcess]` | 增加 Worker，默认 x86；省略脚本时使用中控当前的默认脚本。进程内模式使用中控自身位数。 |
| `xiaoyvctl [--pid PID] remove WORKER_ID` | 删除 Worker；外置直接结束进程，进程内须先停止并完成清理。 |
| `xiaoyvctl [--pid PID] start WORKER_ID` | 启动已停止的 Worker；已断联时创建新进程后启动。 |
| `xiaoyvctl [--pid PID] pause WORKER_ID` | 暂停运行中的 Worker。 |
| `xiaoyvctl [--pid PID] resume WORKER_ID` | 继续已暂停的 Worker。 |
| `xiaoyvctl [--pid PID] stop WORKER_ID` | 请求 Worker 停止脚本。 |
| `xiaoyvctl [--pid PID] terminate WORKER_ID` | 强制结束外置 Worker 进程，保留列表项和日志；进程内不支持。 |
| `xiaoyvctl [--pid PID] logs WORKER_ID [--tail N]` | 读取最近日志；默认 100 行，`N` 可为 1～2000。 |

只有一个可控制中控时可以省略 `--pid`；存在多个时必须先用 `centers` 查询，再指定目标进程。脚本路径支持相对路径，`xiaoyvctl` 会在发送前将其转换为绝对路径。

```powershell
# 查询中控和 Worker
xiaoyvctl centers
xiaoyvctl --pid 12340 workers

# 控制 w1，并读取最近 50 行日志
xiaoyvctl --pid 12340 start w1
xiaoyvctl --pid 12340 logs w1 --tail 50

# 使用另一个脚本增加 x64 Worker
xiaoyvctl --pid 12340 add "E:\另一个项目\dev.lua" --arch x64
```

## JSON 输出

除 `--help` 外，命令结果均为单行 UTF-8 JSON，适合由程序直接读取。

```json
{"ok":true,"centers":[12340]}
```

查询 Worker 和日志时分别返回 `workers`、`logs` 数组：

```json
{"ok":true,"centerPid":12340,"workers":[{"type":"center.worker","replyTo":1,"workerId":"w1","workerArch":"x86","state":"running","text":"正在采集","name":"窗口 1","path":"E:\\我的项目\\main.alpkg","protocolVersion":1,"workerPid":16800,"centerPid":12340}]}
```

```json
{"ok":true,"centerPid":12340,"logs":[{"type":"center.log","replyTo":1,"workerId":"w1","text":"[12:30:01.125] 本轮已处理：10","protocolVersion":1,"centerPid":12340}]}
```

增删和运行控制返回一个 `type` 为 `response` 的结果；失败时 `ok` 为 `false`，并提供 `error`。`replyTo` 和 `protocolVersion` 是协议元数据，普通调用方可以保留但不需要参与业务判断。

`workers` 返回的每个对象包含以下常用字段：

| 字段 | 说明 |
|---|---|
| `centerPid` | 当前中控进程 ID。 |
| `workerId` | 列表项的稳定 ID，例如 `w1`；Worker 进程重建后不变，不是进程 ID。 |
| `workerPid` | Worker 已连接后的进程 ID；连接中或已断联时可能没有该字段。 |
| `workerArch` | `x86` 或 `x64`；进程重新创建后仍使用该位数。 |
| `workerInProcess` | 是否为进程内窗口；为 `true` 时与中控共用进程。 |
| `name` | 中控界面中的窗口名称。 |
| `path` | 当前 Worker 使用的 `.lua` 或 `.alpkg` 路径。 |
| `state` | Worker 当前状态。 |
| `text` | 中控显示的当前常驻文本。 |

运行控制返回成功只表示中控已经接受或处理操作，不表示 Worker 已到达预期运行状态。需要确认最终状态时再次调用 `workers`。`terminate` 会结束进程并保留列表项和日志，下次 `start` 创建新进程。`logs` 返回中控当前仍保留的滚动日志，不是磁盘日志，也不是实时订阅；持续观察时由调用方按需重复查询。

## 状态与退出码

`state` 可能为 `connecting`、`stopped`、`starting`、`running`、`pausing`、`paused`、`stopping`、`error` 或 `disconnected`。暂停、继续和停止的可用状态与中控按钮完全一致。

| 退出码 | 含义 |
|---|---|
| `0` | 命令成功。 |
| `1` | 命令或参数无效。 |
| `2` | 没有找到中控、连接失败或通信失败。 |
| `3` | 中控拒绝请求，例如 Worker 不存在或当前状态不允许该操作。 |
