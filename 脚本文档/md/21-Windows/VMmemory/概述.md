# Windows VMmemory 虚拟机内存

VMmemory 在宿主机访问虚拟机中的进程、模块和内存，Guest 无需安装通信程序。当前用于 **x64 Worker**，通过 `local vm = require("VMmemory")` 按需加载，不注册全局变量。

## 运行前提

- 宿主机必须是 Windows。
- VMware Workstation 官方测试范围为 15.5 及以上；代码不会主动检查版本号。
- Guest 启用 TPM 或 Secure Boot 时暂不支持。
- Worker 需要管理员权限，或当前进程拥有 `SeDebugPrivilege`。
- 虚拟机必须处于运行状态。

## 开始使用

需先取得正在运行的宿主 `vmware-vmx.exe` PID；它不是虚拟机内部的目标进程 PID。宿主需有访问该进程的权限，插件不会自动提权。

```lua
local vm = require("VMmemory")
local hostPid = 1234 -- 替换成当前宿主 vmware-vmx.exe 的 PID
local session <close> = assert(vm.open({host_pid = hostPid}))

-- 枚举 Guest 进程；后续读取使用这里得到的 PID。
for _, process in ipairs(assert(session:processes())) do
    print(process.pid, process.name, process.pointer_bits)
end

-- 查询当前确实存在的进程；同名可能有多个，不自动替用户选择。
local matches = assert(session:processes("notepad.exe"))
if #matches == 1 then
    local pid = matches[1].pid
    local image = assert(session:module(pid))
    local bytes = assert(session:read(pid, image.base, 2))
    print(image.name, tostring(image.base), bytes)
end
```

`<close>` 在离开作用域时关闭会话；也可主动 `session:close()`。普通 userdata 在 GC 时同样会释放，但释放时间不确定。复用会话即可，不必每次读写重新 `open`。

## 加载与数据约定

- 插件及配套运行库由可选插件构建提供，放在 `runtime/x64/`；仅复制 `VMmemory.dll` 不够，须保留配套 DLL、数据和许可证。详见 [open](open.md)。
- 默认只读；需要写入时显式指定 `write = true`。写入不是事务，失败后不会自动回滚。
- 读取使用 Guest 虚拟地址；支持物理访问的方法可传 `vm.PHYSICAL_PID`。地址不是当前 Worker 的本地内存指针，不能交给 `ffi.string` 或 OpenCV 当本地指针使用。
- 64 位地址使用整数、十六进制/十进制字符串或 [address](address.md) userdata；不要经浮点数转换。
- 文本输入输出为 UTF-8；原始字节用 Lua 二进制字符串，允许包含零字节。
- 同一会话的内存操作串行，不同会话可并行。所有会话调用在等待期间让出 Lua VM；第三方调用内部阻塞不能保证立即暂停或停止。

## 错误与部分结果

会话方法完整成功返回 `value, nil, vm.OK`；失败或部分完成返回 `nil, error, status`，有详情时在第 4 个返回值。地址构造、版本和最近错误等模块函数以各自页面为准。

```lua
local data, err, status, detail = session:read(pid, address, 32)
if data == nil then
    print(err, status, detail and detail.completed)
end
```

`PARTIAL`、`LIMIT_REACHED`、`TIMEOUT` 等正状态也不代表完整成功。读写、批量和搜索的详情不同，不能统一当作数据继续使用。状态和标志见[常量与返回状态](常量与返回状态.md)。

函数页中的 `vm`、`session` 沿用上面的初始化；`pid`、`address` 等由调用方替换为已确认的目标进程和地址。写入示例需要以 `write = true` 打开会话，并确认目标空间可写。
