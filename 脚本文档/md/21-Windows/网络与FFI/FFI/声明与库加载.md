---
params: "declarations: string; nameOrPath: string; global: boolean?"
returns: "无、library userdata 或 cdata"
---

**方法名称：** 声明 C 类型和符号，并加载 Windows 动态库。

**语法：**

```lua
ffi.cdef(declarations)
ffi.C.symbol
ffi.load(nameOrPath[, global])
```

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `declarations` | `string` | 是 | cffi-lua 可解析的 C 声明片段。 |
| `nameOrPath` | `string` | 是 | DLL 名称或 Windows 可访问的 DLL 路径。 |
| `global` | `boolean` | 否 | 是否以全局符号方式加载，默认局部加载。 |
| `symbol` | `string` | 是 | 已在 `cdef` 中声明的符号名。 |

| 返回值 | 说明 |
|---|---|
| 无 | `ffi.cdef` 成功时不返回值。声明错误会抛出 Lua 错误。 |
| `library userdata` | `ffi.load` 返回的动态库句柄和符号命名空间。 |
| `cdata` | `ffi.C.symbol` 或 `library.symbol` 对应的 C 数据或函数指针。 |

**详细说明：**

`ffi.cdef` 只解析声明，不编译 C 代码，也不会处理 `#include` 和宏展开。Windows API 的声明必须
匹配实际位数和调用约定，例如 `__stdcall` 与 `__cdecl` 不能混用。动态库卸载和符号生命周期由
运行时管理，调用方不得在库不再有效后继续使用函数指针。

```lua
local ffi = require("ffi")
ffi.cdef[[
    unsigned long __stdcall GetCurrentProcessId(void);
]]

local kernel32 = ffi.load("kernel32")
print(ffi.tonumber(kernel32.GetCurrentProcessId()))
```
