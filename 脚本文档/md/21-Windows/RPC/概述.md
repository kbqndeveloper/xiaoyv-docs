# Worker 互调（RPC）

`local rpc = require("rpc")` 用于同一台 Windows 电脑上的 Worker 互调。x86 和 x64 可以互为服务端、客户端，多个 Worker 可以连接同一个服务；是否通过中控启动不影响使用。

模块已内置，无需额外 DLL。`require` 只取得模块，调用 `rpc.listen` 才开始监听。通信不经过中控、不开放 TCP/HTTP 端口，也不负责启动其他 Worker。服务名称由脚本约定，不是窗口编号或 PID。

## 使用流程

1. 服务端调用 [rpc.listen](listen.md)，用 [server:export](export.md) 注册 Lua 函数，再进入
   [server:run](run.md) 等待请求。
2. 客户端调用 [rpc.connect](connect.md)，通过 [client:call](call.md) 调用已注册函数。
3. 不用时分别调用 [client:close](client_close.md)、[server:close](server_close.md)。

可直接运行的两端脚本见 [x64 服务与 x86 客户端示例](跨位数示例.md)。插件在服务端 Lua 中自由 `require`，再由 Lua 函数封装并导出；不需要把业务功能写进 Worker 源码。

## 数据规则

| 数据 | 传输方式 |
|---|---|
| `nil`、boolean、integer、number | 按值传输；64 位 Lua 整数在 x86/x64 间保持整数精度。 |
| string | 原样传输字节，支持二进制和零字节，不要求 UTF-8。 |
| 无元表的 table | 按值复制；键可为 boolean、number（不能为 NaN）或 string，允许混合键、稀疏数组。 |
| 函数、线程、userdata、原生指针对象 | 不支持直接传输。 |

table 不得有循环引用，接收端不会保留原表身份或多个字段之间的共享引用。一次参数或返回值编码后最多 64 MiB，最多 256 个顶层参数或返回值，嵌套最多 32 层、约 100 万个值；字符串和结构开销都计入大小限制。多个返回值中的 `nil` 会保留，需要存入 table 时可用 `table.pack`。

这不是 `ui.call` 的 JSON 通道，两者的数据类型和大小限制不同。

## 图片、对象和内存

框架不会自动选择传图片路径、像素字节或共享内存。由脚本按任务选择：小数据可直接传，较大的数据可传双方都能访问的文件路径；共享内存需要自行建立并约定格式、尺寸和生命周期。

`cv.Mat`、数据库连接和 VMmemory 对象等应留在创建它们的服务端，由导出的函数操作。把地址转成整数传过去，也只是传了一个数字，不能在另一个进程直接解引用。需要远端对象编号时，编号及其释放规则同样由服务端脚本管理。

## 顺序、暂停和关闭

同一客户端连接的调用按进入该连接的顺序串行执行；服务端按收到请求后的入队顺序逐个执行 Lua 回调，不保证多个客户端同时提交时的先后次序。服务端队列有数量和总字节上限，不应无限堆积请求。

通信等待统一让出 Lua VM，暂停、停止沿用现有运行控制。插件内部正在执行的 native 函数不会被强行中断；一个耗时调用也会让同一服务后续请求等待。不要在回调内同步调用自己，或形成服务间循环等待。

连接中断或调用被停止后不自动重连、不重放请求；需要重新 `rpc.connect`。断开不代表远端操作没有执行，更不代表自动回滚。两个句柄都是 userdata，可由 GC 回收；建议主动关闭，不支持 Lua `<close>` 写法。脚本退出时所属连接和服务一并释放。
