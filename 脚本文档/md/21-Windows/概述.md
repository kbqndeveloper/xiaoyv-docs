# Windows 第一版

Windows 使用 x64 中控，支持独立的 x86/x64 Worker 和进程内窗口；每个窗口拥有独立 Lua VM，大漠仅供 x86 Worker 按需加载。两种界面共用运行控制，页面和脚本按 [开发与打包](开发与打包.md)的来源规则选择；运行位置及故障隔离边界见[中控交互](中控交互.md)。

Lua 与网页可以双向交换 JSON 数据：Lua 使用 `ui.call` 调用页面注册的函数，页面使用 `ui.send` 投递由 `ui.receive` 接收的事件。完整边界见[中控交互](中控交互.md)，页面改造和 JavaScript API 见[HTML 中控自定义与 JavaScript 接口](中控界面/HTML自定义与JavaScript.md)。原有 `print` 和 `print_user` 仍分别用于滚动日志和常驻状态。

命令行脚本、AI 或其他本机工具需要控制中控时，使用[中控外部控制](中控外部控制.md)提供的 `xiaoyvctl.exe`；外部控制默认关闭，只有中控带 `--enable-control` 启动时才可使用。

中控不带参数启动时，自动按同目录 `dev.lua`、`main.alpkg` 的顺序选择脚本。`dev.lua` 用于直接开发调试，可通过 `require/loadfile/dofile` 加载同目录的相对 Lua 文件。

当前可用：

- [`getWorkerInfo()`](getWorkerInfo.md)：读取当前 Worker 的编号、位数和进程 ID；
- `print`、`print_user`、`sleep` 和 `thread`；
- `ui.call`、`ui.receive` 和 `ui.null`；
- [中控脚本 `center.lua`](中控界面/中控脚本.md)：自动执行中控逻辑并管理普通窗口；
- [`require("rpc")`](RPC/概述.md)：本机 Worker 互调，支持 x86/x64 互为服务端和客户端；
- `httpGet/httpPost/asynHttpGet/asynHttpPost`；
- LuaSocket 的 TCP/UDP 和非 TLS 上游模块；
- `ffi`、`require("ffi")`；
- `local cv = require("opencv")`：按需加载可选 OpenCV 5 插件，默认构建不包含；
- [`require("db")`](数据库/概述.md)：按需加载 SQLite 数据库，支持预编译语句、游标、事务和可选 SQLite3MC 加密；
- [`require("VMmemory")`](VMmemory/概述.md)：x64 可选插件，访问虚拟机内存、进程及模块；
- `U2G/G2U`；
- `local dm = require("xiaoyv_hcbyj")`：x86 大漠插件；不预建全局 `dm`，也不自动展开函数。

基础函数直接调用，例如 `sleep(100)`、`getWorkerInfo()`、`httpGet(url)`、`findColors(...)`，不需要额外导出；独立模块仍按各自帮助使用 `thread.newThread`、`ui.call` 或 `require` 等入口。

分模块帮助：[多线程](多线程/概述.md)、[网络与 FFI](网络与FFI/概述.md)、[stb 图像处理](stb图像处理/概述.md)、[OpenCV 5](OpenCV/概述.md)、[VMmemory](VMmemory/概述.md) 和 [SQLite 数据库](数据库/概述.md)。

需要本机 OCR 时，可直接运行外部 [RapidOCRWeb](OCR/RapidOCRWeb.md) 服务并通过 `httpPost` 调用，无需修改 Worker 或把 OCR 模型加入脚本包。

HTML 界面依赖电脑已安装的 Microsoft Edge WebView2 Runtime，原生界面不需要它。HTML 存在但加载失败时仍显示原有错误，不自动切回原生界面。界面不会开放新的 HTTP 监听端口。插件的位数和目录规则见[开发与打包](开发与打包.md#插件与目录)。第一版不照搬 Android `pai`，也不提供独立弹窗 API、自动页面崩溃恢复、`e_print`、WebSocket、`ssl.https`、个性化 VM 和定制大漠偏移自动识别。
