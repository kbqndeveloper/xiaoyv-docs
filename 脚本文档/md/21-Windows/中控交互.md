# 中控交互

Windows 第一版的 Lua Worker 通过日志和常驻状态与中控显示交互；Worker 的启动、暂停、继续和停止由中控按钮控制。

## Lua 可以上报的内容

| Lua 写法 | 中控显示 | 行为 |
|---|---|---|
| `print(text)` | 当前 Worker 的滚动日志 | 追加一行，带 Worker 产生的时间戳。 |
| `print_user(text)` | 当前 Worker 的常驻状态行 | 覆盖上一条状态，不进入滚动日志。传入空字符串可清空。 |

```lua
print_user("正在采集")
print("本轮已处理：10")
```

常驻状态适合显示当前阶段、账号或任务摘要；详细过程和调试信息使用 `print`。

## 中控可以控制的内容

中控负责对选中的 Worker 发送以下控制：

- 启动：创建并运行 Lua VM；
- 暂停：请求暂停主任务和子线程；
- 继续：恢复已暂停的 Worker；
- 停止：请求任务退出并释放运行时；
- 删除：直接结束当前 Worker 进程，任何状态都可以使用。

暂停和停止都需要 Lua 到达运行时检查点。正在执行的大漠、FFI 或其他 native 调用不会被强行
中断；如果 native 调用永久阻塞，可以删除该窗口以强制结束对应 Worker，不影响其他窗口。

## 状态与常驻文本

Worker 的运行状态由对应 Worker 进程上报，中控只负责显示。第一版状态包括：`starting`、`running`、
`pausing`、`paused`、`stopping`、`stopped` 和 `error`。

中控在生命周期变化时会自动更新常驻文本，例如“正在启动”“运行中”“已暂停”“正在停止”、
“已停止”“已完成”和“运行失败”。因此，脚本设置的 `print_user` 内容可能被生命周期提示覆盖；
Worker 继续运行后，脚本可以再次调用 `print_user` 设置自己的状态。

滚动日志是显示用途，不是持久化记录。日志持续大量输出时，Worker 和中控会丢弃较早的日志，
以保证暂停、继续和停止按钮仍能响应；重要业务结果应由脚本自行保存或提交。

## 第一版没有提供的反向接口

Lua 不能读取中控当前选中的 Worker、按钮状态或滚动日志，也不能主动调用中控按钮、创建中控
控件、修改中控布局或动态增加 Worker。需要这些能力时，等后续中控 API 扩展，不要依赖内部
Named Pipe 消息格式。
