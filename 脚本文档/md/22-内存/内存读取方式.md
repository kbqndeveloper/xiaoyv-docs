# 内存读取方式

默认使用 S；需要时切换 P，或在驱动环境满足时使用 K。

| 常量 | 值 | 读取方式 |
|---|---|---|
| `mem.S` | 0 | 默认，process_vm_readv |
| `mem.P` | 2 | /proc/PID/mem |
| `mem.K` | 1 | 内核驱动 ioctl |

**方法名称：** 选择内存读取方式（Android）。

**语法：** 见下方方法表。

**参数说明：** mode 省略时为 S；address 是当前目标中的地址，size 是大于 0 的字节数。

| 方法 | 参数 | 返回值 | 说明 |
|---|---|---|---|
| `mem:setReadBackend(mode?: integer)` | mode：S=0、K=1、P=2，默认 S | 无 | 选择 S=0、K=1、P=2 读取方式，默认 S |
| `mem:init_kerenl()` | 无 | ok: boolean | 初始化 ARM64 外部 K 驱动客户端，保留原接口拼写 |
| `mem:kernelReadMemory(address: integer, size: integer)` | address：目标地址；size：字节数，>0 | bytes: string\|nil | 直接使用 K 后端读取字节 |

| 返回值 | 说明 |
|---|---|
| 无 | setReadBackend 只设置读取方式，不能用返回值判断目标是否可读 |
| ok | K 客户端初始化结果；不能替代实际读到的数据校验 |
| bytes | kernelReadMemory 返回二进制字符串；报告失败时为 nil |

**详细说明：**

## 示例

```lua
mem:setReadBackend(mem.P) -- 后续读取使用 /proc/PID/mem
local value, err = mem:read_memory(address, mem.i32)
assert(value ~= nil, err)
print(value)

mem:setReadBackend(mem.S) -- 恢复默认读取方式
```

初始化 K：

```lua
if mem:init_kerenl() then
    mem:setReadBackend(mem.K)
else
    mem:setReadBackend(mem.S)
    print("K 初始化失败，使用 S")
end
```

## 使用说明

- 设置由对象和线程共享，不随对象销毁恢复；多线程脚本需统一管理。仅切换读取方式，不会把写入和远程调用都切换到驱动；其他 mode 按 S 处理。
- `init_kerenl` 保留原拼写，可能下载并加载外部驱动，实际支持取决于设备、内核和权限。
- `kernelReadMemory` 直接走 K，无需切换读取方式。K 返回非 nil 不能证明驱动填满缓冲区，应结合预期数据判断。
- `mem.S` 是数值读取方式；搜索栈区域使用 `mem.range.S`。
